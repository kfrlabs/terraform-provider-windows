# Contributing

Thanks for helping out. This guide covers the day-to-day workflow; the
[README](README.md) has the full provider documentation.

## Prerequisites

- Go 1.26 or newer, tracked by the `go` directive in `go.mod`.
- Terraform >= 1.11 (WriteOnly attributes require Terraform 1.11+).

## Common tasks

All development tasks go through the `GNUmakefile`:

| Command      | What it does                                              |
| ------------ | --------------------------------------------------------- |
| `make build` | `go install` the provider (`go install ./...`)            |
| `make test`  | Run short unit tests (`go test -short ./... -timeout 120s`) |
| `make lint`  | Run `golangci-lint run`                                   |
| `make fmt`   | `gofmt -s -w .` plus `terraform fmt -recursive examples/` |
| `make docs`  | Regenerate provider docs (`go generate ./...`)            |

## Docs are generated — never hand-edit `docs/`

The pages under `docs/` are generated by `tfplugindocs`. The docs workflow
has a blocking drift gate: `go generate ./...` on a clean checkout must
reproduce `docs/` byte-identically, and any drift fails CI.

If you touch a `Schema(...)` description or anything under `examples/`,
run `make docs` and commit the result.

## Commit messages feed the release notes

Release notes are built from commit subjects (see `.goreleaser.yml`):

- `feat:` and `fix:` appear under Features / Bug fixes.
- `docs:`, `test:`, and `chore:` are excluded from the notes.

Write subjects like `feat: add windows_foo data source` so the generated
notes read well. The scope prefix (`feat(scope): ...`) is optional.

## CHANGELOG

Add an entry under `## [Unreleased]` in [CHANGELOG.md](CHANGELOG.md),
using the same sections as the PR template: Added / Changed / Fixed /
Security. Document the migration there if your change is breaking.

## Acceptance tests

Unit tests (`make test`) run anywhere, including against an in-process SSH
server on loopback — no Windows host needed.

Acceptance tests need a real Windows target with OpenSSH Server. The full
run is:

```bash
TF_ACC=1 go test -tags acceptance ./... -v -timeout 120m
```

For a disposable target, use the throwaway Windows container fixture
described in [test/windows-container/README.md](test/windows-container/README.md):
it builds a `tfacc-win` image on a Windows Server host with Docker, runs it
with a temporary `TFACC_PASSWORD`, and shows the `WINDOWS_HOST` /
`WINDOWS_PORT` / `WINDOWS_USERNAME` / `WINDOWS_PASSWORD` exports plus the
per-group `go test -tags acceptance` invocations to run the suite against it.
